# Notepad3 C-to-C++ migration: completed work

The [active plan](cpp-migration.md) remains authoritative for remaining work and decisions. The following records completed migration work and its validation limits; incomplete validation is not implied to be complete.

## Conversion and integration progress

- The application now calls a stack-allocated C++ `nsUniversalDetector` subclass instead of the UCHARDET C facade; the bundled C API remains for other consumers. The user approved eliminating the detector-object allocation. Real-model parity checks passed on x86/x64 before and after the change, with a test-injected charset-copy failure after the change; the existing encoding regression passed. Fresh isolated linked Release Win32/x64 builds succeeded. Full editor-load/UI behavior and prober-allocation failures remain unverified.
- Execution progress: the `Resample.c` pilot has been converted to `Resample.cpp` without changing the resampling algorithm. The focused real-GDI C-caller harness passed 94 checks on both x86 and x64 before and after conversion; isolated Release/x64 solution builds linked successfully before and after conversion. Other configurations, dialog integration, allocation-failure injection, and GUI smoke coverage remain unverified.
- Lexer progress: all 58 first-party lexer-definition files, containing 62 registered definitions, have been converted to `.cpp` with explicit C linkage and unchanged data. A C-caller harness exercised the extracted production `Style_FillRelatedStyles` with stubbed style calls on x86 and x64 before and after each conversion; isolated linked Release Win32 and x64 solution builds also passed. The two common bases have 23 rows and 22 calls each; Text has 3 rows and 2 calls, and ANSI Art has 5 rows and 4 calls. Actual Scintilla rendering, GUI behavior, Debug and ARM64 remain unverified.
- `EditLexer.c` was converted to `EditLexer.cpp` with C linkage and unchanged behavior. Its focused C-caller harness passed on x86 and x64 before and after conversion, covering comments, folding, and lexer-property dispatch with Scintilla direct calls stubbed; fresh isolated linked Release Win32/x64 builds succeeded. Real Scintilla behavior, GUI integration, Debug and ARM64 remain unverified.
- `Encoding.c` was converted to `Encoding.cpp` with C linkage and explicit casts at four existing heap-allocation sites. A production-unit C-caller harness passed on x86/x64 before and after conversion for INI mappings, encoding lookup and flags, UTF BOMs, UTF-8 validation and a binary Base64 round trip, using a stub encoding table and unused application dependencies. The existing detector regression passed after updating its extracted-source path. Fresh isolated linked Release Win32/x64 solution builds succeeded. Real editor-load/UI behavior, Debug and ARM64 remain unverified.
- `MuiLanguage.c` was converted to `MuiLanguage.cpp` with C linkage and explicit casts at three existing heap-allocation sites. Its C-caller harness passed on x86/x64 before and after conversion for locale lookup, language-setting persistence decisions with INI stubs, fallback strings and formatting using a test resource. Fresh isolated linked Release Win32/x64 solution builds succeeded. Real language-pack loading, menus, Debug and ARM64 remain unverified. A pre-existing potential out-of-bounds access for an unknown locale in `LoadLanguageResources` was observed statically; runtime consequences are unverified and it was not changed.
- `DynStrg.c` was converted to `DynStrg.cpp`, retaining its C ABI, `__stdcall` API and current null/empty behavior. Four heap-return casts, equivalent typed min/max calls, and an unused-function attribute were needed for C++ compilation. Its C-caller harness passed on x86/x64 before and after conversion, including injected initial-allocation and growth failures, mutable-buffer sanitization, formatting and command-line escaping. The WebTemplate consumer harness also passed, as did fresh isolated linked Release Win32/x64 solution builds. Not all allocation-failure paths or PathLib integration cases, Debug or ARM64 were tested. A possible pre-existing descriptor leak remains unmodified and unverified at runtime.
- `PathLib.c` was converted to `PathLib.cpp` with its C linkage and `__stdcall` API retained; `CINTERFACE` preserves C-style COM vtables, and GUID arguments use C++ reference syntax. A production-unit harness linking real DynStrg to C and C++ callers passed on x86/x64 against both the original C and converted C++ source, covering comparison, canonicalization, normalization, quoting, relative, UNC and long-path strings, and known-folder lookup. The existing create-directory regression and fresh isolated linked Release Win32/x64 solution builds passed. Shell links, folder-dialog UI, long-path file I/O, allocation failures, Debug and ARM64 remain unverified.
- `Helpers.c` was converted to `Helpers.cpp` with C linkage and C-style COM vtables preserved. The x86/x64 production-unit C-caller harness passed against original C and converted C++, covering path suffix parsing, quoting, control escapes, string replacement, and controlled worker cancellation and destruction with real PathLib and DynStrg; unrelated application callbacks are failure stubs. Fresh isolated linked Release Win32/x64 solution builds passed. AppID/GUI behavior, failure-injected worker waits, Debug and ARM64 remain unverified. A pre-existing potential allocation-size mismatch in `StrReplaceAll` was observed statically; no runtime overflow test was run and it was not changed.

## Completed conversion and integration stages

These are the original stage instructions retained for context; inventory, characterization, and final validation still continue for remaining work in the active plan.

3. **Prove one mixed-language conversion.** The initial pilot converted `Resample.c` to `Resample.cpp` while retaining its algorithm, attribution, API and filter selection; the unreviewed `_tmp` draft was not substituted. Preserve C linkage and calling convention where remaining C code or external exports require it, and update the main project, filters, scripts and tests in the same change. Fix actual C++ compilation/link errors rather than applying a project-wide `/TP` or broad warning suppression. Run focused tests plus compile and linked-build checks. Verify remaining C units and existing C++ units link together before expanding.

4. **Convert the remaining first-party units in small dependency-aware batches.** The representative `styleLexCPP` prototype and conversion passed the scoped Win32/x64 checks above. Preserve the existing trailing-array layout, sentinel/row contents and mixed linkage; if the layout cannot be preserved for a subsequent lexer, stop and agree a representation before bulk conversion. Select lower-level utilities and application units (`Encoding`, `Helpers`, `MuiLanguage`, `Dlapi`, `Dialogs`, `Styles`, `FindReplace`, `Edit`, `Notepad3`) based on actual header/linkage dependencies. Convert `DynStrg` and `PathLib` as needed for a fully C++ first-party build, while keeping their observable contracts initially. Each batch renames files, updates `.vcxproj`/`.filters`, native-test paths and extractors, maintained companion references, and relevant documentation; report alternate-project impact without changing it. Run affected focused tests and a linked build before proceeding. Check `extern "C"` around both declarations and definitions, including C++ source files that currently wrap whole C headers; do not put C++ templates/types inside `extern "C"`. Check `__stdcall`, function pointers, C-only constructs, keywords, initialization, conversions, `const`, layout and diagnostics. Preserve existing C-style COM interfaces and `lpVtbl` calls during initial compilation where feasible; verify macros and include order before Windows COM headers, reference counts and callbacks. Ask before changing COM behavior or undertaking a broader interface rewrite. Do not blanket-convert vendored sources.

5. **Replace integration shims deliberately.** Inventory actual callers and symbols, including remaining C consumers. Retire only C-language interop whose callers have migrated. For TinyExpr, extract or redesign the compatibility logic as a typed C++ application-facing interface and replace the old C facade only after parity tests pass; preserve position mapping, locale, `log`, variable lifetime, parse/evaluate and error semantics. Retain the existing Scintilla typed layer for this plan; further evaluation of vendored `ScintillaCall` is a post-plan open point. Preserve Lexilla creation/ownership and PCRE2's C ABI and regex engine semantics; do not modify vendored patches without separate approval.

## Resampler draft: review disposition

The `_tmp` files are untracked user work, not an approved dependency or a drop-in replacement. Static comparison only; no build, output comparison or runtime validation has been performed.

| Priority | Finding | Evidence and consequence |
|---|---|---|
| High | Current filter missing | `src\Dialogs.h:254` selects Lanczos8; `_tmp\ImageResampler.hpp:11-16` exposes only Box, Bilinear, Mitchell and Lanczos3. Adopting its default changes the filter and may change the app's DPI-scaled images. |
| High | Invalid or partial input handling differs | `_tmp\ImageResampler.hpp:141-161` rejects nonpositive sizes but has no 4096 limit and treats any nonzero `GetDIBits` scanline count as success. The original clamps output dimensions and requires all source scanlines (`src\Resample.cpp:258-267,296`); partial reads could produce an incomplete result. |
| High | Allocation and size failures differ | The draft allocates multiple vectors and tables without catching allocation exceptions or checking multiplication/aggregate sizes (`_tmp\ImageResampler.hpp:96-124,160-170`); its failure can escape callers that currently expect a null result. Audit 32-bit overflow, large downscales and failure paths before any use. |
| Medium | Sampling and output differ | The draft uses half-pixel centers, clamped edge contributions and rounding (`_tmp\ImageResampler.hpp:107-124,133-134`); the original uses a different center, skips out-of-bounds samples and truncates (`src\Resample.cpp:464-482,509-515`). It also returns a top-down DIB section instead of a compatible bitmap (`_tmp\ImageResampler.hpp:193-198`, `src\Resample.cpp:276`). Pixel and GDI-consumer behavior require comparison, not assumed equivalence. |
| Medium | API and failure contract differ | The draft has no custom filter entry point and does not preserve the original error codes (`src\Resample.h:66-84`, `src\Resample.cpp:130-141,252-255`). `ResampleImageBitmap` currently retains the original bitmap on failure (`src\Dialogs.cpp:7154-7175`). |

Any later replacement is a separate proposal: compare all supported filters, custom filters, same-size and scale-boundary cases, alpha/color channels, 24/32-bit inputs, dimensions, GDI ownership and error paths against the original, including partial reads and injected allocation failures. Obtain approval for intended visual or API differences before integrating it; preserve required attribution and licensing.
